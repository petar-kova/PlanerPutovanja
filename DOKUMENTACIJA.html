1. Pregled projekta

Planer Putovanja je web aplikacija za organiziranje putovanja. Korisnik se može registrirati, prijaviti, kreirati putovanje, dodati destinacije, aktivnosti i troškove, pratiti budžet putem dashboarda te spremiti uspomene u albume sa fotografijama. Plan putovanja moguće je izvesti kao PDF dokument.

Aplikacija je izgrađena prema MVC (Model–View–Controller) arhitekturi koristeći ASP.NET Core 8. Vizualni identitet je moderan, temeljen na principima glassmorphisma, 3D CSS transformacija i responzivnog dizajna.

AktivnostiDodavanje aktivnosti po danu i satu unutar putovanja

3.2 Opis ključnih modela

Trip.cs – Model putovanja

public class Trip {
    public int Id { get; set; }
    public string Name { get; set; }          // Naziv putovanja
    public string Destination { get; set; }   // Glavna destinacija (tekst)
    public DateTime StartDate { get; set; }   // Datum polaska
    public DateTime EndDate { get; set; }     // Datum povratka
    public decimal Budget { get; set; }       // Planirani budžet (€)
    public TransportMode Transport { get; set; } // Enum: Auto, Avion, Vlak, Autobus, Brod
    public string UserId { get; set; }        // Veza s korisnikom (strani ključ)

    // Navigacijska svojstva – EF Core automatski učitava vezane podatke
    public List<TripDestination> Destinations { get; set; }
    public List<TripActivity> Activities { get; set; }
    public List<Expense> Expenses { get; set; }
    public TripAlbum Album { get; set; }
}

DashboardViewModel.cs – Podaci za dashboard

Ovaj model nije direktno u bazi – konstruira se u kontroleru iz postojećih podataka:

public class DashboardViewModel {

    public List<OverBudgetTripItem> OverBudgetTrips { get; set; } // Upozorenja
    public List<MonthlyExpenseItem> MonthlyExpenses { get; set; } // Za line grafikon

}

ContactMessage.cs – Kontakt poruka

public class ContactMessage {
    public int Id { get; set; }

    [Required(ErrorMessage = "Ime je obavezno")]
    public string Name { get; set; }

    [Required, EmailAddress]
    public string Email { get; set; }

    [Required]
    public string Subject { get; set; }   // Tema upita

    [Required, MinLength(10)]
    public string Message { get; set; }   // Tekst poruke

    public DateTime SentAt { get; set; } = DateTime.UtcNow;
}

Data Annotations kao [Required], [EmailAddress], [MinLength] automatski generiraju validacijska pravila i poruke o grešci, i na serveru i na klijentskoj strani.

4. Kontroleri i logika

4.1 HomeController – kontakt forma

// GET – prikazuje praznu kontakt formu
public IActionResult Kontakt() => View(new ContactMessage());

// POST – prima podatke iz forme, validira i sprema u bazu
[HttpPost]
public async Task<IActionResult> Kontakt(ContactMessage model)
{
    if (ModelState.IsValid)
    {
        _context.ContactMessages.Add(model);
        await _context.SaveChangesAsync();
        TempData["ContactSuccess"] = true;       // Poruka za sljedeći request
        return RedirectToAction("Kontakt");       // Redirect sprječava dvostruki submit
    }
    return View(model);  // Vraća formu s greškama
}

4.2 TripsController – upravljanje putovanjima

Koristi [Authorize] atribut – samo prijavljeni korisnici mogu koristiti. Svaki upit filtrira po UserId pa korisnik vidi samo svoja putovanja.

U Details akciji koristi se Eager loading s Include() za učitavanje vezanih podataka u jednom upitu:

var trip = await _context.Trips
    .Include(t => t.Destinations.OrderBy(d => d.Order))
    .Include(t => t.Activities.OrderBy(a => a.Date))
    .Include(t => t.Expenses)
    .Include(t => t.Album).ThenInclude(a => a.Photos)
    .FirstOrDefaultAsync(t => t.Id == id && t.UserId == userId);

4.3 DashboardController – analitika

Gradi DashboardViewModel iz podataka u bazi:

  • Zbraja sve troškove i budžete korisnika
  • Računa postotak potrošnje: (troškovi / budžet) × 100
  • Pronalazi nadolazeća putovanja: StartDate > DateTime.Today
  • Pronalazi putovanja iznad budžeta: troškovi ≥ 90% budžeta
  • Grupira troškove po putovanju za grafikon
  • Broji najčešće destinacije za bar grafikon

4.4 AlbumsController – uspomene i fotografije

Fotografija se ne uploaduje kao datoteka, nego se sprema kao URL adresa slike (npr. Unsplash link ili direktan URL). To je namjerna odluka kako bi se izbjeglo upravljanje lokalnim datotekama na serveru.

5.4 Tipografija

.section-title {
    font-size: clamp(2rem, 4vw, 3.2rem);  /* Responzivna veličina */
    font-weight: 950;                      /* Extra-bold */
    letter-spacing: -1.5px;               /* Negativni razmak – moderan izgled */
    color: var(--primary);
}

clamp(minimum, preferirano, maksimum) – automatski prilagođava veličinu fonta:

  • Na malim ekranima: minimalno 2rem
  • Na střednjim ekranima: 4vw (4% širine viewport-a)
  • Na velikim ekranima: maksimalno 3.2rem
Aplikacija intenzivno koristi visoke font-weight vrijednosti (850, 950) kako bi naslovi izgledali moderno i snažno, u skladu s "display" tipografskim stilom.
